# Nordic catalog sorting

Swedish and Finnish readers see Å, Ä and Ö as distinct letters after Z. Danish and Norwegian readers see Æ, Ø and Å after Z. Danish/Norwegian Aa follows the platform collation's Å grouping. Canonically equivalent spellings receive the same primary key; the original stored text and book/entity ID break ties so paging is stable.

The catalog uses the reader's language at query time. A valid `?lang=` override wins, followed by the signed-in account language and the browser's language preferences. OPDS uses its authenticated reader, including Basic Auth, independently of a browser login. The existing OPDS default applies when no stronger language choice is available. The sorting locale is passed as a bound SQLite function argument; changing readers does not change a reused database connection's locale.

Swedish (`sv`), Finnish (`fi`), Danish (`da`), Bokmål (`nb`, including the existing `no` alias) and Nynorsk (`nn`) use this policy. Regional forms such as `sv-SE` are accepted. UI translation availability remains separate: Danish or Nynorsk sorting can be selected with the existing `?lang=da` or `?lang=nn` mechanism even when that UI translation is unavailable. Following OPDS navigation and paging links preserves the override. No untranslated language is added to the account's UI selector.

Publisher lists sort their displayed names, including Calibre imports whose optional publisher sort field is empty. Book title and author sorts, standard author/series/tag/publisher lists, Classic table text sorts, letter filters, OPDS and named alphabetical shelf/magic-shelf sorts share the same keys. Manual shelf order, recent reading order, date/numeric sorts and language codes retain their own meanings. Classic list/grid filters use the server's letter labels instead of applying a second browser accent fold. Downloads retain their existing non-catalog labels. OPDS's All entry and letters are paginated as one sequence, so neighboring pages do not repeat a boundary letter.

Nordic sorting uses ICU already supplied by the platform through Python's standard library. It installs no additional package. The published Linux environment and macOS provide this library; the adapter validates the expected Nordic order and index data before using it. If the native capability or data is unavailable at startup, a warning is logged and that execution context retains the complete previous sorting policy. It does not silently mix native and fallback keys within one query. A native key failure after initialization fails the query instead of displaying an empty library as though no books existed.

Other languages retain the existing Latin accent folding, Spanish ñ distinction and non-Latin letter policy. Native sort keys are temporary query values; they are not written into library metadata or reused across ICU upgrades. This is Nordic tailoring, not a general Unicode alphabetic-index implementation for every script.
