## 1. Witness of bytes actually executed — NOT IMPLEMENTED

OBSERVED: the current witness (pytest_evidence.py:11) compares a frame filename
with the target path. It does not establish source content or code provenance.
The parent target-byte check remains before child startup.

A loader-read hash is a useful necessary observation, but not sufficient for the
requested property. The import protocol permits a loader to read one source and
execute another code object. Two concrete reproductions below read the intended
mutant bytes and nevertheless execute VALUE = 1, with passing tests.

Design assessment: I cannot establish the requested whole-class guarantee with
the current mutable, in-process observation/reporting design. A replacement
would need a defined trusted path from intended source through compilation and
the exact code object actually executed, including custom loader behavior.
Checking the code object's filename, hashing a loader read, or moving the same
check to another hook does not provide that path.

This is not a proof that no possible implementation can solve the problem.
It is a refusal to claim closure from another adjacent observation. No loader
prototype was promoted into production; no before/after repair claim is made.
