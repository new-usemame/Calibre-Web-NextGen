## 1. Mutation integrity

Implemented in prepare_mutation/apply_mutation and the isolated phase's mutation
argument: exactly one nonempty byte anchor, changed replacement bytes, stale
source refusal, byte-preserving application after scrub and before preflight.
The no-op is refused before even the provenance pytest probe is launched.

Already covered for the OLD execution route: tests/unit/test_mutation_harness.py:452
(test_a_stale_anchor_is_an_error_never_a_verdict) and :468
(test_an_ambiguous_anchor_is_also_an_error). Those do not substitute for the new
isolated API tests. Existing scrub ordering is covered at :301
(test_sweep_scrubs_after_cleanup_and_again_before_each_phase).

New check tests: test_integrity_refuses_invalid_plan_before_execution and
 test_integrity_preserves_bytes_and_refuses_stale_or_noop_application.
A permissive implementation was executed first; all five cases failed by not
raising IsolationError. It was then replaced with the guards.

Command (retries 0, no maxfail):
```sh
"$ROOT/repo/.venv/bin/python" -m pytest tests/unit/test_mutation_harness.py -k integrity -q -o addopts='' -p no:rerunfailures -p no:flaky --tb=short
```

## 2. Collection accounting

Implemented: successful collection exit; complete structured pytest telemetry;
nonempty unique real node IDs resolving to files within the tree; selected-count
agreement; terminal-summary numerator, denominator and deselection agreement;
collection/setup/teardown errors rejected as infrastructure failures. The observer
uses pytest's real session items and reports, not node-looking stdout lines.
No prior leg implemented these accounting checks. Leg 3's provenance rejection
is retained at test_provenance_rejection_prevents_phase_execution (:554), but is
not counted as collection-accounting coverage.

Tests: test_collection_accounting_rejects_unsound_selection (14 negative cases),
test_collection_accounting_accepts_selected_numerator, and
 test_collection_real_pytest_selected_numerator. Setup failure received a separate
red run before its guard was added. Real pytest 9 emits the expected 2/3 numerator.

Commands: absolute interpreter, -m pytest tests/unit/test_mutation_harness.py,
-q -o addopts='' -p no:rerunfailures -p no:flaky --tb=short; red selections
-k collection_accounting_rejects and then
-k 'collection_accounting_rejects and setup_error'; green selection
-k 'collection_accounting or collection_real' with -s.
