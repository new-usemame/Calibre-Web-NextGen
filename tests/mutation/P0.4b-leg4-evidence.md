## 3. Exit-code and summary discipline

Implemented: only pytest 0/1 can describe normal execution; 2–5, signals and
unknown codes are infrastructure errors. A terminal summary must exist, parse
unambiguously and agree with structured per-node setup/call/teardown reports.
Selection membership/counts must match validated collection. Exit 1 requires
both a reported failed test and an actually failed call; exit 0 forbids failures.
Baseline execution must pass before the mutant is allowed to execute.

No prior leg implemented these checks. Leg 3 already fixed the authority label
(test_diagnostic_labelling_cannot_be_bypassed, :568); it is retained and cannot
be promoted by these predicates. New signals are TEST_FAILURE and TESTS_PASSED,
not authoritative verdict labels. Group 4 still owns execution eligibility and
durable final publication.

Tests: test_execution_rejects_infrastructure_exit_codes (seven codes),
test_execution_summary_and_reality_guards (12 negative cases),
test_execution_real_broken_baseline_stops_mutant, and
 test_execution_real_clean_baseline_and_visible_mutation.

Exact mutations and test selections are in check_mutations.py:14. Both output
files contain real per-variant pytest summaries, Mac/APFS only. Exit 1 is
recorded as a killed experiment, not an authoritative mutation verdict; the
backend remains diagnostic. Other exit codes invalidate the experiment.

Initial campaign: 29 variants, 23 killed and six survivors. Every survivor:

| Variant | Disposition | Evidence and resolution |
| --- | --- | --- |
| write_verification | Genuine test gap, fixed | Partial writes were untested. New test_integrity_detects_incomplete_write at :933 injects truncation; removing the reread guard now fails that test. |
| numerator | Genuine test gap, fixed | Original numerator defect also violated denominator accounting. New numerator_only at :684 changes only the selected numerator with no deselection; the removed numerator guard now fails. |
| schema_version | Genuine test gap, fixed | Missing/incomplete reports were tested but unsupported versions were not. Added schema_version at :684; removed version guard now fails. |
| failed_summary | Defense in depth | Removing summary-failure guard alone survives because the actual-call guard still rejects exit 1 without failure. |
| failed_call | Defense in depth | Removing actual-call guard alone survives because summary agreement plus the summary-failure guard reject the same input. |
| equivalent_integer_bound | Equivalent | The integer actual_failures counter makes < 1 and <= 0 identical; it starts at zero and increments by one per failed call. |

OBSERVED composed variant COMPOSED_failed_summary_and_call removes both exit-1
failure guards. It is killed (1 failed, 45 passed, 47 deselected in 2.92s,
Mac/APFS only), by exit_one_without_failure. Thus either guard alone suffices
given summary/report agreement, and their joint removal is observable.

OBSERVED new gap tests were red on the corresponding temporary-copy mutants
before green on the implementation:
```text
write_verification: KILLED; 1 failed, 48 passed, 47 deselected in 2.81s
numerator: KILLED; 1 failed, 48 passed, 47 deselected in 2.86s
schema_version: KILLED; 1 failed, 48 passed, 47 deselected in 2.88s
```
Together with unchanged initial results: 26 of 29 variants killed; remaining
three are the two explained defenses and one equivalent comparison. No genuine
gap remains from this campaign. This is a bounded mutation sample, not a claim
of exhaustive defect discovery.

Design finding: two checks of a consistent failure count are redundant. The
composed experiment makes that explicit. The collection numerator case was
different: the original fixture accidentally coupled independent inconsistencies
and masked a missing assertion. It needed an independent test, not a
defense-in-depth excuse.
