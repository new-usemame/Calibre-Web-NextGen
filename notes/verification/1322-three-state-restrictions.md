# Boolean and enumeration view restrictions (#1322)

The requester catalogs both physical books and ebooks and needs to hide physical entries using a custom column. Boolean restrictions therefore expose Yes, No, and Undefined independently; enumeration columns use the existing literal-value policy. Undefined includes both an absent value row and a nullable value row. An allow list is an OR of the selected states; a deny list excludes its selected states even if they overlap the allow list. Empty lists leave visibility unrestricted. Canonical persisted Boolean tokens are `true`, `false`, and `undefined`; Yes/No and old numeric aliases are accepted.

Switching to a Boolean column rejects incompatible saved global or account restrictions before applying the rest of the configuration form. This avoids silently deleting restrictions or broadening book access. Malformed persisted Boolean tokens fail closed. The shared policy covers the ordinary single-user catalog filter and the multi-user/device visibility calculation. Existing text and enumeration values retain their literal semantics.

Classic remains the existing administration surface for these advanced settings; the New UI already links there. Global, per-account, and bulk controls offer translated Boolean state labels. A real Bootstrap/X-editable defect found during verification needed string-only internal widget keys: jQuery coerced true/false into booleans, and the Undefined key did not match its translated label. Internal `bool:` keys never reach persisted/API values.

OPDS search also exposed a pre-existing identity gap: HTTP Basic authentication selected the OPDS user, while the search query implicitly filtered and joined status for the cookie user. Search and its read/archive joins now accept the explicit OPDS identity, followed by the same shared content/exposure policy as other feeds. Browser search callers keep their existing defaults. This repair is necessary for the requested restriction to work in reader clients as well as the web catalog.

The portable browser regression uses the actual served classic configuration page, table.js, Bootstrap and X-editable. It failed with the old script when Yes rendered as Empty and passed with the fix, exercising canonical add/edit/delete values and switching between tag/Boolean modes.

The OPDS SQLite regression failed before the identity repair, and now covers an unrestricted cookie account and a more restrictive, conflicting cookie account; it also checks that returned read/archive state belongs to the Basic-auth reader. Final focused OPDS, three-state, authentication, shared-book, API search and advanced-search bulk-ID checks: 87 passed.

Private real-column verification uses owned proof books and accounts at desktop 1280px and phone 375px, real configuration/modal endpoints, and actual catalog/API/OPDS requests. The running app received only matching db.py/opds.py and table.js overlays; SHA-256 matched the reviewed source for all three, with the original private seed retained.
