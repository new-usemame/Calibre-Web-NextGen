## 2. D-R-prime labelling — OBSERVED

PhaseResult and DiagnosticObservation are frozen, slotted data classes whose
status=UNVERIFIED and authoritative=False fields cannot be supplied to the
constructor or dataclasses.replace. Mapping compatibility lets existing callers
read observations without gaining a writable status dictionary. asdict includes
both fixed fields. The terminal independently downgrades any non-error label,
including stale caller-provided labels, and exits nonzero for diagnostics.
No OS-name switch grants authority; this harness has no strong backend yet.

This is an API/terminal invariant against accidental promotion, not a security
boundary against arbitrary Python code deliberately altering class internals.
The inherited-token backend cannot grant authority even after provenance passes:
the mutant is abnormal input and can remove its own ownership token while the
conversion wrapper creates a new session. Both cited cps files were read only.

The old shared-checkout CLI execution mechanism is not migrated in this leg.
Only its result type and terminal labelling change, so it cannot remain an
alternate path to authoritative output. Existing anchor and restoration checks
remain, without adding parent deliverable 4's verdict-accounting work.
