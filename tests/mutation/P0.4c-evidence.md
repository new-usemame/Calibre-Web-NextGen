## 1. Container-per-phase primitive

OBSERVED: `container_backend.py:50` implements a pinned Git archive copied into
a fresh container for each phase. Only the disposable output directory is
mounted. The source checkout, shared Git directory and host interpreter are
not mounted. The image ID is resolved once. Container removal precedes return.
The primitive is not yet wired into the mutation CLI or granted verdict authority.

OBSERVED negative controls, common command plus selections/env below:

```text
CWNG_CONTAINER_TEST_FAULT=cleanup
-k 'test_container_tokenless or test_container_setup_failure'
4 failed, 132 deselected in 9.31s
exit: assert remaining == '' (container still present)
timeout: AssertionError: tokenless detached writer survived container removal
failure: assert remaining == '' (container still present)
setup interruption: container still present

CWNG_CONTAINER_TEST_FAULT=seed
-k test_container_phases_copy
1 failed, 135 deselected in 1.04s
AssertionError: pinned source VALUE = 1 check failed inside container
```

The fault mode lives exclusively in the test fixture, which removes its exact
created container IDs after the assertions, including during failed tests.
The cleanup fault also suppresses the runner's own removal check so the tests
independently witness the defect. No unrelated containers are removed.

OBSERVED green, common command plus `-k test_container_ -rP --show-capture=stdout`:

```text

CONTAINMENT failure: alive_writes=4 after_removal_writes=0 containers=0
```

These are counts in the shared output file, sampled again one second after

is absent. Kernel lifetime semantics, rather than that finite sampling interval,
are the basis for descendant containment.
