{# Custom-column VALUE editor for the classic interface. Renders IN PLACE on /custom_column/, the same way the new interface's "Edit values" replaces the browse view rather than opening anything over it. A modal was tried first and was wrong on both counts the users noticed: it covered the tree it was editing, and it was a small box in the middle of a screen that had plenty of room. The panel is server-rendered from `edit_rows` (see web.py::cc_value_edit_rows), which already carries each node's `available` flags — computed by the same hierarchy.node_availability the JSON tree publishes. So this partial holds no rules: whether a value may be deleted or used as a merge source is decided once, in hierarchy.py, and read here and by the SPA alike. cc_value_editor.js only adds the two things the server cannot precompute, because both depend on what the user has selected right now: which rows may receive the cut value, and which rows may host a merge. Those are the only client-side rules, and the script names the server-side rule it mirrors. Gated on `may_edit_values`, which is current_user.role_edit() — the same permission every value-write endpoint enforces. #}
