## 1. Mechanism ESTABLISHED before fix

Command: "$PY" tests/mutation/leg9_probe.py
The probe copies the harness into an independent temporary directory, instruments
PermissionError at the os.killpg raise site, and runs the exact isolated timeout
case. It records only group/process IDs, UID and state, never argv/environments.

OBSERVED before fix (second reproduction; first independently showed the same):
    EPERM_AT_RAISE {"pgid": 85546, "signal": 9, "group_probe": "errno-1", "members_pid_pgid_uid_state": [["85546", "85546", "501", "Z"]], "direct_child_returncode": null, "direct_child_reaped": false, "table_returncode": 0}
    EPERM_AT_RAISE {"pgid": 85546, "signal": 9, "group_probe": "errno-1", "members_pid_pgid_uid_state": [["85546", "85546", "501", "Z"]], "direct_child_returncode": null, "direct_child_reaped": false, "table_returncode": 0}
    1 failed in 1.91s
    PROBE_EXIT=1 (Mac/APFS only)

The independent control changes only the state of its own freshly created child,
leaving the zombie unreaped until the probes finish. Real output:
    CONTROL live own group: killpg(signal=0) OK
    CONTROL own unreaped zombie: kill(pid, 0) OK
    CONTROL zombie-only group: killpg(signal=0) errno=1
    CONTROL zombie-only group: killpg(signal=9) errno=1
    CONTROL direct child reaped: returncode=0

This establishes a zombie-only group EPERM, not an ownership permission failure.
Apple's published XNU kern_sig.c killpg1 filters SZOMB group members, then returns
EPERM when the POSIX path finds no eligible member. The observed OS behaviour
matches that source; the installed kernel's exact source revision is not claimed.
Source: https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c#L1612-L1621

Fix: only after PermissionError, inspect a fresh all-user group table. Suppress
that error only for a nonempty group consisting entirely of same-UID zombies.
Live, mixed, foreign-UID, absent, malformed and failed inspections do not qualify.
The cleanup loop still reaps the direct child and waits for descendant zombies
to disappear; this does not declare zombies reaped. No skip/xfail was added.

Regression command: "$PY" -m pytest tests/unit/test_mutation_harness.py
-k group_signal_handles -q with the standard options, --tb=short.
An initial test-authoring run lacked the signal import and is NOT red evidence.

## 2. Non-positive PGID guard — corrected; reuse limit explicit

_signal_group refuses pgid <= 0 with IsolationError before entering os.killpg.
Regression uses an intercepted kernel call, never a real signal to zero/negative
IDs. Command: "$PY" -m pytest tests/unit/test_mutation_harness.py
-k nonpositive_ids -q with standard options, --tb=short.
OBSERVED before guard:
    E   Failed: DID NOT RAISE <class 'mutate.IsolationError'>
    3 failed, 128 deselected in 0.22s
After, -k 'nonpositive_ids or group_signal', --tb=no:
    10 passed, 121 deselected in 0.19s

PID reuse assessment: NOT fully defended. Popen can reap the group leader before
cleanup; snapshots/birth-time checks do not reserve a numeric PGID through the
signal syscall. The inspection-error fallback uses the numeric PGID too. Removed
the misleading comment suggesting the snapshot prevents group ID reuse, and
added the explicit limit to ISOLATION.md. A complete defense would retain stable
ownership through the last signal; another identity snapshot would still race.
No signal was sent to an unrelated group to test this hazard. This assessment
comes from inspection of the lifetime and call sites, not a live reuse experiment.
