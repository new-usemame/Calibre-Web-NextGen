### Fixed
- **Users auto-created from a reverse proxy get a usable email address.** When the proxy sends the user's email as the username (Cloudflare Access does), the new account was given `name@example.com@localhost`, which fails validation on the next profile save, so that user could never set a password for OPDS or other Basic Auth clients. The email is now the proxy's email header or the username when either is a valid address no other account has, and otherwise a placeholder that passes validation.
- **A reverse-proxy login whose identity is an existing account's email logs into that account.** If an admin created "rob" with rob@example.com and Rob then signed in through the proxy as rob@example.com, auto-create tried to add a second account with the same email and failed on every request. Only the proxy's identity header is matched, never Remote-Email or X-Remote-Email.
