# Reviewed v1 torrent file metadata

Slice 8 fixes valid original EPUB descriptors rejected solely because they carry optional per-file SHA1 metadata or ordinary single-file hidden/executable flags. The implementation admits reviewed fields while preserving bounded decoding, raw info-dictionary hashing, explicit tracker origins, credential isolation and safe file containment.

The primary format references are [BEP47](https://www.bittorrent.org/beps/bep_0047.html), [BEP3](https://www.bittorrent.org/beps/bep_0003.html) and [BEP27](https://www.bittorrent.org/beps/bep_0027.html). BEP47 remains a draft; this change supports the reviewed subset rather than claiming full extension support. SHA1 is only a hint. Piece hashes remain canonical torrent integrity, and CWNG import identity remains SHA-256 of actual selected bytes. Unknown single-file attributes, symlink semantics, single-file padding, web seeds, bootstrap nodes and pure v2 fields remain unsupported; reviewed hybrid support is documented separately in [virtual-library-hybrid-torrents.md](virtual-library-hybrid-torrents.md). Multi-file padding contributes to the exact piece count but cannot be the only positive payload. Valid zero-length companion files remain allowed.

## Observed evidence

- Before the fix, legal single/multi-file descriptors generated from an original local EPUB failed `invalid_torrent`. Released native libtorrent 2.0.11 parsed both and returned the expected v1 hashes. After the fix, CWNG returns those same hashes. The native wheel was independently checked against official PyPI digest/size and installed only in an isolated external test directory. No product dependency or torrent network session was added.
- Behavioral parser and adapter tests were seen red before implementation. Both qBittorrent and Transmission submissions preserve exact raw descriptor bytes and hash acknowledgements. Invalid SHA1 lengths/types, symlink metadata, inconsistent piece totals and malformed private flags are refused. A fresh independent probe found a padding-only descriptor accepted; its regression was seen red before requiring positive non-padding payload.
- `acquisition_torrent_metadata_runtime_probe.py` drives the production worker, killable child HTTP transport, Transmission adapter and normal ingest processor against a loopback RPC contract fixture. Single-file and padded multi-file original EPUBs each submit once with exact descriptor bytes, persist their v1 identity, earn independent receipts and Calibre records, and leave source bytes/paths/permissions unchanged. Executable source permissions are not inherited by the ingest copy. The same probe using the pre-slice validator fails before submission with `invalid_torrent`.

The loopback RPC server is a contract fixture, not a real Transmission peer download. The native libtorrent observation is a released parser seam, not qBittorrent WebUI or live downloading. Historical real-client results remain documented in [virtual-library-clients.md](virtual-library-clients.md); they are not current-field execution evidence. Required candidate-image CI, independent recheck, security review and immutable image proof are recorded in the PR description once earned. No provider, public tracker, household service, schema, UI or per-user connection change is involved.

A pre-existing compatibility boundary remains: CWNG structurally accepts a descriptor with a 1 GiB piece length that native libtorrent 2.0.11 refuses. BEP3 states no maximum; this slice does not claim that every structurally consistent piece size is accepted by every client. Normal client rejection remains an explicit failed request.
