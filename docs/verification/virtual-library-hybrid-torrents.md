# Reviewed hybrid torrent files

Original legal BEP52 hybrid descriptors can pass the existing Torznab download and import path. V1 and v2 must describe the same files, ordering and lengths; piece-alignment padding and SHA-256 piece-layer roots must agree. The bounded canonical parser hashes the exact original info bytes only after validation, preserving SHA1 for Transmission and exposing SHA256 for qBittorrent identity selection. The format reference is [BEP52](https://www.bittorrent.org/beps/bep_0052.html).

qBittorrent reports its engine through the existing authenticated `app/buildInfo` API. Reviewed libtorrent 1.2 uses the v1 ID, and 2.0 uses the first 20 bytes of the v2 ID, matching its released `get_best()` selection. That ID is used consistently for the pre-existing-torrent check, acknowledgement, durable worker record, recovery and file lookup. Unknown engine responses fail before upload or the durable submission fence. A manual retry after restoring a supported engine can submit once. Ordinary v1 files and magnets make no new engine request. Transmission retains its v1 contract.

The validator retains the 512 KiB descriptor, 16-depth, 16,000-node and 1,000-file limits. V2 paths require safe NFC UTF-8 components, no controls or case aliases, no symlinks, and no mixed file/directory leaf. Repeated synthetic `.pad/<size>` entries are accepted only with exact hybrid padding attributes, size and position; any real-path collision is rejected. Layers must have the required count and root, with no extra roots. Pure v2 and `btmh` magnets, web seeds, bootstrap nodes and unreviewed extensions remain unsupported. Descriptor validation establishes structural consistency; the download client still verifies actual pieces. Selected book identity uses actual SHA-256 bytes and the existing containment/receipt checks.
